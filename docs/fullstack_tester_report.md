# تقرير مراجعة Full‑Stack وTester لمشروع CarRental

**تاريخ المراجعة:** 2026-08-24
**الفرع:** `fix/portable-windows-config`
**نطاق المراجعة:** API، Clean Architecture، SQLite، المصادقة والصلاحيات، MVC، Flutter، ملفات تشغيل Windows، Swagger، Postman، والاختبارات من طرف إلى طرف.

## 1. الخلاصة التنفيذية

تمت مراجعة النظام باعتباره منتجًا متكاملًا وليس مجموعة مشاريع منفصلة. النتيجة الحالية مستقرة وظيفيًا: API وMVC يشتركان في قاعدة SQLite، تطبيق Flutter يتصل بمسارات العميل فقط، عمليات الإدارة محمية بدور Admin، وعمليات العميل معزولة بدور Customer. لم تظهر أخطاء فشل في بوابة الاختبار النهائية.

> **الحكم النهائي:** لا يوجد عطل وظيفي مانع في النسخة التي تم اختبارها. توجد ملاحظة تشغيلية واحدة متوقعة: مفتاح JWT وحساب المدير الافتراضيان مخصصان للتطوير المحلي، ويجب استبدالهما قبل النشر العام.

| Flutter | الجلسة، المصادقة، الكتالوج، الحجز والإلغاء، التواريخ، الثيم | التحليل والاختبارات ناجحة |

## 4. السيناريوهات الحرجة التي تم اختبارها

تم اختبار إنشاء وتعديل وحذف السيارات، رفع الصور والتحقق من نوع الملف وحجمه، منع حذف سيارة عليها حجز نشط، منع الحجز أثناء الصيانة، منع إعادة فتح حجز على سيارة تحت الصيانة، التحقق من تعارض التواريخ، إكمال وإلغاء الحجوزات، تحديث حجز مغلق، منع الوصول المجهول، ومنع خلط توكنات Admin وCustomer.

كما تم اختبار تدفق التكامل المشترك: أضيفت بيانات السيارة من خلال الإدارة، ثم ظهرت في كتالوج العميل عبر API وقاعدة SQLite المشتركة. وتم التحقق من أن حجز العميل يظهر في تاريخ الحجوزات الإداري.

## 5. ملاحظات الاختبار والتفسير

ظهر أثناء اختبار MVC أن إعادة التوجيه بعد دخول المدير كانت إلى `/` بدل `/Dashboard`. هذا ليس عطلًا؛ فالمسار الافتراضي في MVC معرف على أنه `Dashboard/Index`، ولذلك يمثل `/` صفحة Dashboard نفسها. تم تعديل اختبار الـSmoke ليقبل المسار الصحيح بدل تسجيل فشل كاذب.

يظهر أثناء تشغيل Flutter تحذير بناء غير قاتل متعلق بتوقع خط CupertinoIcons، مع العثور على MaterialIcons. لم توجد مراجع فعلية لـ`CupertinoIcons` في كود التطبيق، والتحليل والاختبارات والبناء نجحت؛ لذلك صُنّف التحذير كملاحظة أدوات وليس عطلًا وظيفيًا.

ملفات CMD لا يمكن تنفيذها حرفيًا داخل بيئة Linux الحالية لعدم وجود Windows CMD أو PowerShell. تمت مراجعة أوامرها ومساراتها نصيًا، كما تم تشغيل الأوامر المكافئة والتحقق من API وMVC وFlutter وPostman داخل البيئة، واختبر المستخدم تشغيل MVC فعليًا على Windows بنجاح.

## 6. التشغيل المعتمد

من جذر المشروع على Windows:

```powershell
.\Setup-CarRental.cmd
.\Run-CarRental.cmd
```

يشغل الملف الكامل API على `http://localhost:5109` وMVC على `http://localhost:5110`. للإيقاف استخدم:

```powershell
.\Stop-CarRental.cmd
```

ولتكرار التحقق:

```powershell
.\Run-Tests.cmd
.\Run-API-Tests.cmd
.\Run-Postman.cmd
```

## 7. ملاحظة ما قبل الإنتاج

إعدادات التطوير تتضمن مفتاح JWT وحساب مدير مخصصين للتشغيل الأكاديمي والمحلي. حماية بدء التشغيل تمنع وضع Production عند استخدام القيم الافتراضية أو المفاتيح القصيرة. قبل النشر العام يجب وضع مفتاح JWT وكلمة مرور المدير في Secret Manager أو متغيرات بيئة آمنة، ويفضل الانتقال إلى إدارة هويات متعددة المستخدمين بدل الحساب الإداري الثابت.
